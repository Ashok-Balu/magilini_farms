# Database Seeding Setup

## Overview
The database seeding is **RESTRICTED by default** to prevent accidental data loss. Seeding is disabled in all environments via `ENABLE_SEED=false`.

## Current Seed Data
All environments are configured with identical seed data for testing and development:

- **Categories**: Mangoes, Farm Fresh
- **Products**: Premium Alphonso Mango, Organic Farm Fresh Greens, Fresh Farm Eggs (with multiple variants)
- **Coupons**: WELCOME10 (10%), SUMMER20 (20%), FREEDELIV (delivery), FLAT100 (₹100 flat)
- **Pincodes**: Karur, Coimbatore, Chennai, Hyderabad, New Delhi
- **Business Hours**: Monday-Sunday with standard opening hours (8am-8pm, Saturdays 7am-9pm)

## How to Run Seeding

### Prerequisites
1. MongoDB must be accessible
2. Set `ENABLE_SEED=true` in your environment's `.env.*` file
3. Use `--force` flag when running the seed command
4. Set `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD`; the password must contain at least 16 characters

### For Development Environment
```bash
cd backend
# Temporarily enable seeding
# Edit .env.development: ENABLE_SEED=true

# Run seeding (does NOT override existing data)
npx cross-env NODE_ENV=development npm run seed -- --force

# If the database already has data, use --clear to reseed from scratch
# npx cross-env NODE_ENV=development npm run seed -- --force --clear

# IMPORTANT: After seeding, disable again in .env.development: ENABLE_SEED=false
```

### For Testing Environment
```bash
cd backend
# Temporarily enable seeding
# Edit .env.test: ENABLE_SEED=true

# Run seeding
npx cross-env NODE_ENV=test npm run seed -- --force

# If the database already has data, use --clear to reseed from scratch
# npx cross-env NODE_ENV=test npm run seed -- --force --clear

# IMPORTANT: After seeding, disable again in .env.test: ENABLE_SEED=false
```

### Production Environment
Production seeding is always blocked. The application will reject any attempt to run the seed script against the production database.

## Safety Features

1. **ENABLE_SEED Flag**: Must be explicitly enabled in environment files
2. **--force Flag Required**: Seeding will not execute without `--force` argument
3. **Production is always blocked**: Never run the seed script against the production database
4. **No built-in credentials**: The administrator is created only from explicit seed credentials; no sample customer or shared-password accounts are created
5. **Data Preservation**: By default, seeding uses UPSERT - existing data is NOT deleted unless `--clear` flag is used
6. **Automatic Disabling**: Always set `ENABLE_SEED=false` after seeding

## To Wipe and Reseed Everything

Use the `--clear` flag to remove all existing data first:
```bash
NODE_ENV=development npm run seed -- --force --clear
```

**⚠️ WARNING**: The `--clear` flag will delete all data in these collections:
- Products
- Categories
- Coupons
- Pincodes
- Business Hours
- Customer Users (but preserves admin users)
